## 1. Direction

**The mechanical digest is the floor.** Every day finalizes, validates,
freezes, and is pushed to the repository whether or not any inference
provider is authenticated or has quota. Model layers (item summaries,
plain-language lines, Day in Review, section quick-reads, discovery
tags) are additive; when they are absent the digest says so, per day,
in its own prose, and the Coverage Statement's arithmetic still
reconciles. A provider outage is a disclosed gap, never a missing day
and never a silent retry loop. This is the operating principle GUIDE
§2 (no silent omission) and §6 r13/r14 (a ceiling makes a disclosed
gap, not pending work) already imply for items; this plan extends it to
the provider itself.

## BUG-1 — LLM client: backoff, server hint, backend fallthrough

- **Why:** two HTTP calls in ~1 s against a provider asking for 3–40 s;
  an unrecognized `LLM_BACKEND` silently becomes the CLI.
- **Files:** `src/fapd/llm.py`, `src/fapd/config.py`,
  `tests/test_llm.py`, `docs/code-standards.md` §1 seams,
  `docs/agents/editorial.md` (replace "CLI-backend zero-token failures"
  wording; state plainly there was no backoff between 3e88577 and this).
- **Diff sketch:** `GeminiBackend.complete` (and `AnthropicBackend` for
  its 429/529) → `_call_with_backoff`: up to
  `LLM_TRANSIENT_ATTEMPTS = 3` calls, wait `min(server_hint or
  2**n, LLM_RETRY_MAX_WAIT_S = 60)`; hint parsed from `retryDelay` /
  `"retry in Ns"` / `Retry-After`; every attempt ledgered zero-billed
  with its error (existing `_log` contract). `LLMClient.complete` keeps
  its one outer retry but waits the same bounded interval. Unknown
  `LLM_BACKEND` → `ValueError` at construction, listed values only.
  Read 3e88577's body first and record in the commit why its removal is
  being reversed.
- **Alternatives:** raising `_TRANSIENT_RETRIES` alone (same minute
  window; rejected); unbounded honoring of the hint (a 24 h hint would
  hang the finalizer; rejected — the cap exists for that).
- **Risk:** longer EOD under sustained 429; bounded by attempts × cap
  and by FEAT-1's circuit breaker. Tests: hint parsed; cap respected;
  N ledger rows then one `LLMError`; non-transient errors not retried;
  unknown backend rejected.
- **Verification:** `uv run pytest tests/test_llm.py -q`.
- **Rollback:** constants default to today's values (1 retry, 0 wait).

## FEAT-1 — Provider-unavailable model

- **Why:** "no provider authenticated or with tokens" must be a first-
  class state the pipeline can read, not an exception class it trips
  over thirty times.
- **Files:** `src/fapd/llm.py`, `src/fapd/config.py`, `.env.example`,
  `tests/test_llm.py`, `docs/agents/editorial.md`, GUIDE §6 r7 (name
  the `none` backend).
- **Diff sketch:**
  - `NullBackend` (`LLM_BACKEND=none`): every call ledgers a zero-token
    row `error="provider disabled (LLM_BACKEND=none)"` and raises
    `ProviderUnavailableError(reason="disabled")` — a subclass of
    `LLMError` so nothing downstream needs a new except clause.
  - Per-run circuit breaker in `LLMClient`: after BUG-1's attempts are
    exhausted on a **quota/auth-class** error (429 RESOURCE_EXHAUSTED,
    401/403, the CLI "organization has disabled" envelope), the client
    sets `self.unavailable = reason` and every later call in that
    process short-circuits with `ProviderUnavailableError` — ledgered,
    zero tokens, no HTTP. Transient 5xx does **not** trip it (the next
    batch may succeed). `LLMClient.status()` → `{"backend", "model",
    "unavailable": reason|None}` for the pipeline's disclosure and the
    health surface.
  - Missing key for the configured backend (`GOOGLE_GEMINI_API_KEY`
    unset with `LLM_BACKEND=gemini`, etc.) → `unavailable="not
    authenticated"` at construction, not a stack trace mid-batch.
- **Alternatives:** a pre-flight probe call (spends a request, can be
  wrong a minute later; rejected); a global "LLM off" env only (covers
  the configured-off case, not the quota case; kept as the `none`
  backend, insufficient alone).
- **Risk:** a mis-classified error could switch a whole run to
  mechanical; the classification table is explicit and tested per
  backend, and the disclosure names the reason so a wrong trip is
  visible in the digest itself.
- **Verification:** tests: `none` ledgers and raises; breaker trips on
  429 not 503; status reflects it; missing key → unavailable.

## BUG-2 — Finalizer degrades; ladder spacing is policy

- **Why:** one `LLMError` currently costs the day; the retry ladder's
  timing is an accident of the worker backoff.
- **Files:** `scripts/run_pipeline.py`, `src/fapd/collect.py`,
  `src/fapd/config.py`, `tests/test_run_pipeline.py`,
  `tests/test_collect.py`, `docs/continuous-ingestion.md` §9,
  `docs/agents/operations.md`.
- **Diff sketch:**
  - `stage_analyze`: each layer call wrapped; `ProviderUnavailableError`
    / `LLMError` → recorded as `layers[name] = {"ran": False, "reason":
    …}` and the stage continues (with the breaker tripped the remaining
    layers short-circuit instantly). The stage returns the layer map;
    `stage_render` passes it to `report.render` (FEAT-2) and writes it
    to the run's provenance manifest entry. Validation is unchanged: a
    digest that fails a gate still fails the attempt.
  - Ladder: `EOD_FINALIZE_RETRY_MINUTES = (15, 60, 200)`,
    `EOD_MAX_FINALIZE_ATTEMPTS = 4` — attempts ≈04:00, 04:45, 06:15,
    09:55 UTC. With BUG-2 the ladder is for *validation* failures and
    crashes, not provider outages (those now finalize mechanically on
    attempt 1); the spacing still matters for the retained cases.
    Values are operator policy.
  - Stages 1/1b/1c/2 stay idempotent and are re-run per attempt as
    today (they are how a late Record issue gets in).
- **Alternatives:** moving `EOD_ET_HOUR` later (hides the problem,
  delays every digest; rejected). Skipping render when analyze fails
  (the current behavior; rejected by GOV-1).
- **Risk:** the finalizer will now freeze a mechanical digest on a
  night the operator would previously have re-run by hand for prose.
  That is the designed behavior under GOV-1; OPS-1 is what keeps prose
  in the digest.
- **Verification:** stubbed-layer tests for the four branches (all ran /
  provider disabled / breaker tripped mid-run / validation failure);
  ladder timing test; full suite.

- **Why:** a digest without prose must still be a digest: every selected

- **Files:** `src/fapd/report.py`, `digests/TEMPLATE.md`,

  - Header table gains an **Inference** row with exactly two states:
    the normal one, naming the attribution the ledger already records

    digest owes anyway), and the mechanical one: **"No inference was
    available for this publication day. All content is source-derived

  - Sections 1–5 and 9: an item selected by the rules but lacking a

- **Risk:** long mechanical listings on heavy days (a 300-item CREC

## FEAT-4 — Explicit provider failover (shipped 2026-09-05)

- **Why:** GUIDE §6 r7 permits it; OPS-1(c) wants it; it is not needed
  for the floor. `LLM_BACKEND_FALLBACK=<name>`: used only after the
  primary trips the FEAT-1 breaker, logged at WARNING, ledgered under
  its own `backend` value. The digest's Inference row names only the
  provider/model that actually produced the prose (the r7 attribution),
  never why the primary was bypassed; the failover event itself is in
  the manifest and the operations report. Not before FEAT-1 and FEAT-2
  exist — a failover without correct attribution is the "silent
  provider change" r7 forbids.
- **Shipped 2026-09-05**, on the incident that made it non-deferrable:
  on 2026-09-01 the CLI's session limit was open from 00:08 UTC, the
  04:28 finalizer's first call exhausted the ladder and tripped the
  breaker, and compose/sections/tags were skipped — the digest published
  with no Day in Review, and the limit reset at 04:40, four minutes
  after the finalizer stopped. Built as designed above, with two
  additions the design did not anticipate. First, the hop **re-resolves
  the model tier** for the provider it moves to: `haiku` is `haiku` on
  the CLI and `gemini-2.5-flash` on Gemini, so carrying the primary's
  resolved name across would call a model that does not exist there.
  Second, attribution needed a plural: `status()["backends_used"]` and
  `day_inference.backend` now hold every provider that produced prose
  for the day (`cli, gemini`), because recording only the client's
  current backend is false in one direction and only the original is
  false in the other — exactly the "attribution false" r7 names.
  Scoped to the finalizer (`run_pipeline.py`, `digest.py`); the
  continuous `AnalyzeWorker` is deliberately unchanged, since a
  free-tier quota spent on all-day map/plain work is not there at 04:00.
